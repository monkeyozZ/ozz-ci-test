# Ozz Console v3：完整交互原型

在浏览器打开 [index.html](index.html) 即可体验，无需启动服务或后端。项目、服务、资源、任务和规划共用一份内存数据；刷新重置演示资源，主题在本机保存，列表筛选通过 URL 保留，历史返回恢复阅读位置。

本版取代早期只覆盖创建主路径的简版。按用户已确认的方向采用 Zeabur 的项目创建页、项目内服务导航、服务六页签和添加服务命令面板，补齐 Ozz 当前管理能力与独立规划流程。参考范围是本次在 Chrome 实际查看的创建项目、项目服务工作区、添加来源与 Docker 配置；管理业务与能力边界仍以 Ozz 源码和 [覆盖规划](coverage-plan.md) 为准。

## 先体验这条路径

1. 点击项目列表中的“个人博客”，直接进入 `web` 服务。左侧包含返回项目、项目资料、整合、新建服务与服务列表；服务顶部提供“服务状态、环境变量、用量、网络、硬盘、设置”。
2. 点击“新建服务”，用鼠标或方向键选择 GitHub、Docker、应用模板、数据库。选择 Docker 后可输入 `nginx:1.28.3-alpine3.23`，端口改为 `80`。面板内返回上一步会保留各来源草稿；关闭会确认未保存输入，再次添加从新的创建会话开始，已经保存的服务仍保留在项目中。
3. 点击“核对部署配置”会先保存服务草稿并固定服务 ID，再在同一个面板检查来源、资源、端口和存储。点击“确认发布”才创建部署任务；“稍后部署”保留草稿。返回修改继续保存同一个服务，保存响应未知时先核对原请求。失败沿原记录创建独立重试，不会重复创建服务。
4. 修改环境变量或挂载后“保存草稿”，运行中的已发布快照保持独立。停止、恢复与重启使用原已发布快照；新草稿需要再次部署。
5. 回到项目列表创建项目：先选择部署位置，名称可选。提交后直接打开首个服务来源面板。只有多个环境时，项目内才显示切换器。

顶栏“交互原型 · 演示数据”可切换慢响应、下一次任务失败、未知结果、版本冲突、列表失败、空态、缺少 Git 集成、会话到期和恢复只读。它们只改变本地状态。

| 入口 | 可操作范围 |

| 服务器 | Server 登记/编辑/受限移除、指纹发现与确认、只读预检、固定版本安装任务、集群导入与同身份更新、能力与节点观察 |
| 设置 | GitHub/Registry/Builder 创建/编辑/验证、仓库/分支/Webhook、凭证/到期/替换/引用保护、全局与集群入口、外观、平台诊断与恢复指引 |

Environment 组织同一项目下的一组服务、配置、域名和数据；数据库是其中的服务。创建项目自动建立 production；默认隐藏单环境选择，保留 `Cluster → Project → Environment → Service` 归属。切换环境不会移动服务、复制数据库或更改项目的 Cluster。production、有服务或保留数据的环境不能直接删除。

## 内置模板与真实边界

五个模板均为固定模板版本 **1.0.0**，取自 [catalog.ts](../../packages/control-plane/src/templates/catalog.ts) 与 [image-assets.ts](../../packages/control-plane/src/templates/image-assets.ts)。镜像版本与模板版本分别展示；四个内置镜像携带源码中固定的 SHA256。

| 模板 | 镜像输入 | 默认端口 | 默认数据卷 | 请求 CPU/内存 → 上限 |
| --- | --- | --- | --- | --- |
| Docker | 用户填写 OCI 镜像 | 8080 | 无 | 100m/128 MiB → 500m/256 MiB |
| Node.js 示例 | `node:24.22.1-alpine3.24` | 8080 | 无 | 100m/64 MiB → 500m/128 MiB |
| 静态站点示例 | `nginx:1.28.3-alpine3.23` | 80 | 无 | 25m/32 MiB → 250m/64 MiB |
| PostgreSQL | `postgres:17.11-bookworm` | 5432 | 4 GiB | 100m/256 MiB → 1000m/768 MiB |
| Redis | `redis:7.4.11-bookworm` | 6379 | 1 GiB | 100m/64 MiB → 500m/256 MiB |

Node.js 使用预构建运行时与固定示例程序；静态站点使用 Nginx 欢迎页面。Git 来源仍通过 Dockerfile 构建。数据库是单写入实例、只提供私有连接，初始化凭证随数据身份保留；local-path 申请容量不等于硬配额。

卷引用区分草稿、已发布、在途和实际观察。保存挂载不伪造实际绑定；新 PVC 等待消费者，发布或维护 helper 成功后再记录绑定观察。维护锁阻止相关部署与运行操作，未知/失败/取消不会直接解除维护锁。删除服务与销毁卷分别确认，服务删除保留数据。

保存手工备份/恢复记录只登记操作者证据，不执行数据导出、导入、完整性验证或切流。F26–F50 中尚未接入当前 API 的部分明确为规划演示，记录保存在独立的 `planningRuns` 集合，不会冒充 Deployment / Operation。自动备份、通用变量引用、回滚、终端、AI、文件管理、迁移等仍需要相应真实实现。
