# Zeabur 交互参考

2026-10-29 在用户 Chrome 的已登录页面，通过可见网页控件实际打开项目列表、创建项目、现有项目、添加服务、Docker 配置、数据库分类和 Git 表单。没有提交创建或部署，也没有读取秘密值。Chrome 的网页 JavaScript 控制始终不可用；本次使用原生网页控件完成观察，研究标签页已关闭，临时控件读取状态已恢复。

| 场景 | 实际观察 | Ozz 的对应处理 |
| --- | --- | --- |
| 创建项目 | 从列表进入完整创建页，先选部署目标，名称可选，最后创建 | 名称可自动生成；一个目标仍只引用一个 Cluster，关联服务器不能变成重复调度目标 |
| 项目内导航 | 左侧替换为项目名、位置、设置/整合、添加服务、服务列表；进入项目直接呈现服务 | 以服务工作区为核心，保留项目总览入口；单环境不重复呈现 Environment，多个环境时提供明确切换 |
| 添加服务 | 在原服务页上打开命令面板，来源逐行选择，有返回与键盘提示 | GitHub、Docker、应用模板、数据库；保留原服务作为背景与返回位置 |
| Docker 配置 | 镜像与认证、服务信息、变量、端口、卷、命令、健康检查；附加部分逐段展开 | 不丢配置项；凭证引用沿用现有加密保存机制，端口和必要校验可见 |
| 返回操作 | Docker 配置取消后回到来源列表；来源面板关闭后回到原服务 | 保留草稿及原服务，核对失败或发布失败不重复创建对象 |
| 数据库 | 同一面板内显示数据库列表，返回回到来源列表 | 采用现有 PostgreSQL、Redis；原型不把其他数据库伪装成当前内置模板 |
| Git | 同一面板内选择仓库来源、名称、分支、根目录及认证 | 使用已实现的 GitHub 连接、仓库与 Dockerfile 构建；构建器与镜像仓库保留可修改入口 |
| 服务详情 | 名称/身份在上，服务状态、环境变量、用量、网络、硬盘、设置横向切换 | 将 Ozz 配置、发布记录、日志、网络和存储安排在服务内，保留真实能力与状态区别 |
| 服务状态 | 突出实例状态、来源和位置，并提供域名与日志等快捷入口 | 草稿、发布快照、实际观察仍分别表达；发布与操作任务可以追踪 |

Zeabur 的来源列表还有其他产品能力，Ozz 不因此宣称已实现文件管理、终端、第三方 Git Provider 或其他数据库的一键部署。现有功能及规划能力的完整入口对应见 [coverage-plan.md](coverage-plan.md)。编号覆盖本身不证明原型操作已完成，最终检查必须走完对应操作及结果。
