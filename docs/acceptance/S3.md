# S3 服务与镜像发布：实施和本地验收

日期：2026-10-26（Asia/Shanghai）。S3 实现、本地产品流程与 Linux ARM64 部署验收已通过，云端运行与其他架构仍待资源就绪后补验。本记录区分真实产品流程、受控协议/数据库测试及云端关口；范围和退出条件沿用 [开发计划 S3](../development-plan.md#6-s3镜像部署引擎)。

## 已实现

- Service 继承 Environment → Project → Cluster，配置草稿与已发布快照分开；端口、资源、副本、命令、探针、变量及 `.env` 解析有权威校验。秘密在事务内转为加密引用，历史 Deployment 保留引用版本。
- Deployment 固定目标、配置、镜像摘要及阶段；同服务发布与 Operation 共用持久变更槽、幂等和任务恢复。完整应用后记录 published，健康等待失败不回退成最近成功版本。
- Kubernetes 资源使用台账、UID、nonce、revision 和所有权校验。停止保留配置，恢复只使用已发布版本；完整重发与启动停止中的服务需要显式意图。
- 服务/Pod 观察与当前 Metrics；失联保留最后观察，过期与未知保持可见。旧观察不能冒充新发布的健康结果，Pod 快照需与其受管 ReplicaSet 模板一致。
- Pod 日志采用受控 HTTPS 与 SSE，包含 Pod/容器/previous 选择、有限尾部与 follow。最多 1,000 尾行、60 秒、1 MiB 原始及编码后输出、账号 4 个连接；HTTP 下游另有 65 秒截止时间。已知秘密按该 Pod 的快照跨分片脱敏，未知快照拒绝读取。
- Vue Console 的项目内服务、服务创建与草稿、差异/发布确认、部署阶段和持久日志、Pod/指标、运行操作与相关路由已经接入真实 API。镜像任务明确没有构建日志。
- 发布失败时保留有界的 `failureObservation`：当时的差异、资源状态与 Pod 身份，不包含原始容器配置、环境变量或事件消息；后续观察刷新不会覆盖它。应用未完成时 `result` 仍为 `null`，失败证据不能冒充完整已应用快照。

`tests/probes/s3-local-lab.mjs` 使用受保护的本机密码和持久 state，仅针对已登记的本地测试项目。任务原请求和幂等键保留；脚本可从检查点继续，不删除原记录或将错误改成成功。报告中的历史检查保留实际观察时间，不表示同一检查在每次续跑时都重新执行。

二次发布曾暴露两类问题：历史 Secret 必须与完整台账核对，不能只使用当前版本的必需资源列表；滚动期间分开读取 ReplicaSet/Pod 列表可能看到不同时间的状态，需要具名核验缺失的控制器或已消失的 Pod，并将不完整观察排除出健康成功。两类问题均有确定性回归。第二次真实失败的原观察已被刷新，不能精确断言当次原因；保留其失败终态，关联重试 `f161a8e8-65e1-4c17-9cbb-ebc09707c116` 已恢复成功，随后新增持久失败证据防止再次丢失现场。

Worker 恢复使用 `--worker-crash` 扩展：仅在核对本项目注册 PID、命令、工作目录，以及没有其他活动任务后发出 SIGKILL；通过正常 Worker 启动与租约恢复接续。最新真实失败证据的任务为 `cf9df0a7-abc0-44e9-88f6-9458cca58ca3`，其测试服务已删除，历史结果仍可查看。
