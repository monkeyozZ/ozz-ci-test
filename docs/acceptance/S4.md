`sync` 只读，不改变域名意图或远端对象。服务合法重发后，原失败任务不能改用新版本重试；独立 `reconcile` 以新任务重新应用当前可信绑定，保留 hostname / Domain ID / portId。生产切换仍是独立动作，接受前核对有效 staging 证书及新鲜 DNS，验证来源和时间进入任务，重试保留原证据。

## 本地证书测试边界

固定 [Pebble v2.10.1](https://github.com/letsencrypt/pebble/releases/tag/v2.10.1) 与 [测试资产锁](../../infra/local-lab/networking.assets.lock.json)。Linux/Darwin ARM64 二进制已从官方资产下载并校验 SHA256。[本地端点生命周期验证](s4-local-acme-fixture-results.json)通过：显式 CA 验证、默认信任拒绝、UDP/TCP DNS、幂等启动与保留文件的停止/启动。所有模拟 challenge 监听和跳过验证开关均禁用，实际 HTTP-01 已在后续产品验收中经过 Traefik 验证。测试 CA 仅显式传给客户端和 Issuer，不改全局 DNS 或证书库。

Pebble 的账户、订单和签发根保存在内存；重复启动保留原进程，真正重启会重置签发状态。运输层 CA、配置和日志持久保留。短期叶证书用于自动续期验证，本地 `production` 端点仍属于测试签发。

真实产品验收使用独立 S4 项目，不复用或替换 S3 留存服务。A/B 都已观察到新的叶证书序列、指纹和到期时间，TLS 主机名及各自测试 CA 校验成功，默认系统信任仍拒绝。Worker 在 B 的 `domain_reconcile` 已确认一个资源写入后收到 SIGKILL，原任务重领到成功，保留原 hostname、portId、UID 与 nonce，实际 HTTPS 继续返回原应用。

真实 UI 首轮四项业务操作均成功，但末尾用例的请求头采集方法没有取得 Chromium Origin；失败报告保留。修正为 `headerValue()` 并等待采集后完整重跑通过。手机端同时修复成功 toast 盖住解绑确认按钮的问题；[390 深色确认截图](../../apps/console/tests/artifacts/s4-real-final/unbind-390-dark.png)及按钮命中检查证明有三条 toast 时仍可立即确认。已人工复核[真实 1440 浅色详情](../../apps/console/tests/artifacts/s4-real-final/domain-1440-light.png)。

证书观察携带 `authority`。`local_test` 显示为本地测试证书，浏览器默认不信任，不能生成公网可信 HTTPS 入口；`unknown` 也不能生成。Let's Encrypt staging 证书始终属于测试签发。`NETWORK_LOCAL_ACME_CONFIG_FILE` 仅在 development/test 进程允许，production 启动拒绝此配置。

cert-manager 已完成版本与资产核验：[v1.21.3](https://github.com/cert-manager/cert-manager/releases/tag/v1.21.3) 的 [支持矩阵](https://cert-manager.io/docs/releases/)覆盖 Kubernetes 1.33–1.36；本地为 1.35.9。官方清单共 47 个对象，最大单对象 JSON 为 146,637 bytes，安装路径需要独立、有上限的请求容量；现有工作负载默认上限不放宽。**版本核验不代表安装或签发通过。**
