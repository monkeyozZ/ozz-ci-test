# S2 服务器与多个独立集群：本地实现和验收

日期：2026-10-25（Asia/Shanghai）。对应 S2.01–S2.08，覆盖 F05–F07、F17 的节点观察，以及 F02/F09/F23–F25 的接入部分。**真实本地导入、初始化、后台观察失联恢复、浏览器流程和工程检查均已通过。真实 VPS 初始化、云网络和 Oracle 运行容量尚未验收，S2 全阶段未标记完成。**

本文以运行记录与源代码为证据。S1 的 Compose 成绩不代表新 S2 Linux 镜像已验证，B04 协议探针也不代表 S3 日志或 S7 终端产品已交付。

## 实际实现

- [Infrastructure Adapter](../../packages/infrastructure/src) 使用 `ssh2` 1.17.0 和官方 `@kubernetes/client-node` 2.0.1；控制面沿用 Node 24.22.1、Nest/Fastify、Prisma/PostgreSQL、BullMQ 与独立 Worker。ESM Kubernetes SDK 经动态 import 使用，不改变整个工程模块制式。
- [接入命令、执行器与观察器](../../packages/control-plane/src/infrastructure) 复用 Operation/Outbox、租约、generation、取消与恢复锁。API 只受理和查询，SSH/远端 API 长操作交由 Worker。Server/Cluster 的在途互斥有 PostgreSQL 部分唯一索引；迁移见 [202610250003_s2_infrastructure](../../packages/database/prisma/migrations/202610250003_s2_infrastructure/migration.sql)。
- SSH 先无认证发现主机公钥，再以独立可信来源确认；未信任或指纹改变时不能继续认证。只读预检记录机器身份、OS/架构、CPU/内存/磁盘、端口、权限及已有 K3s。初始化固定安装身份、Cluster、机器、节点名和 API 地址，校验官方资产 SHA，不覆盖未知安装，也不关闭整机防火墙。
- Kubernetes 导入严格解析嵌入式配置，拒绝 exec、外部文件、代理及跳过 TLS。Worker 验证真实 CA/SAN 和 `kube-system` UID；候选更新失败保留原有效连接。CA 变化要求显示并确认旧/新摘要，不能借更新地址将已有项目改投另一集群。
- Node 以 `(clusterId, uid)` 区分，只有已验证且唯一匹配的机器身份才关联 Server。Cluster 保留 Node、能力、只读工作负载和真实 Metrics 观察；配置容量、预检磁盘与当前使用量分别呈现，未知保持 `null`。
- 独立双槽观察器使用数据库观察租约、退避和连接 revision 校验。单次成功快照与历史错误分开保存；API 和控制台按 90 秒时效呈现未知/过期，不把断联当成 stopped。具体调度和故障证据见下表，未完成项不能从实现存在推断通过。
- 控制台接入 Server 指纹/预检/初始化、Cluster 候选连接/CA 确认、Node/能力/工作负载和通用任务页。秘密提交后清空输入，不写入浏览器持久存储；任务可查看、取消、重试和刷新恢复。

完整端点、请求体和响应范围见 [S2 API 契约](../api-contract-s2.md)。能力发现只证明配置与当次观察；IngressClass/Traefik 存在不等于 HTTPS 已可访问，StorageClass 存在不等于持久卷恢复已通过，远端标签也不能独立证明平台所有权。

## 真实本地拓扑与路径

[实验环境](../local-lab.md)为 macOS 14.8 / M1 Pro / 16 GiB 上的三台 Lima VZ VM。每台 2 CPU / 2304 MiB / 20 GiB 稀疏盘，Ubuntu 24.04 ARM64、K3s `v1.35.9+k3s1`。控制面在宿主运行，PostgreSQL/Redis 使用本项目 Docker 容器。

| 路径 | 实际结果 |
| --- | --- |
| A / B 导入 | 产品保存加密候选 kubeconfig，经 Worker 验证各自 TLS/集群身份/Node 后建立连接；未重新安装原集群 |
| C 初始化 | 干净 Linux 经产品指纹发现、独立信任、只读预检和异步 Worker 初始化，最终验证 Secret 静态加密，Server 与 Cluster 共享同一 Node 关联 |
| 三集群归属 | 三个节点都叫 `ozz-node`，各有不同的集群 UID、Node UID 和 CA；三个 Project 分别固定绑定 A/B/C，且各自创建默认 production |
| 资源保留 | 项目、集群、任务、VM 磁盘和身份均保留，供后续开发使用。当前运行状态以 `scripts/local-lab.mjs status` 及产品观察为准 |

C 首次初始化在加密确认阶段失败，错误码为 `SSH_ENCRYPTION_NOT_ENABLED`；已发生的安装保留。随后只读检查确认 `enable=true`，执行器改为严格解析 JSON 的布尔字段并有界等待最多 30 秒，再从原失败 Operation 创建关联重试，恢复成功。原始失败 stdout 未保存，精确根因未能证明；不将“启动期竞态”当作已确认结论。

失败证据为 [首次运行报告](s2-local-first-attempt.json)，安装前证据为 [C 干净预检](../../infra/local-lab/acceptance/s2-c-preflight.json)，成功与身份关系见 [产品接入报告](s2-local-results.json)。本地已经存在的初始化和项目不应再次卸载/重装来刷通过次数。

## 复现与权限

依照[开发说明](../development.md)启动现有控制面、按[本地运行面说明](../local-lab.md)启动 A/B/C。不要重新初始化管理员或替换既有主密钥。下列命令不输出凭证明文：

```sh
pnpm api:generate
pnpm check
pnpm exec node --env-file=.env tests/probes/s2-local-lab.mjs
pnpm exec node --env-file=.env tests/probes/s2-observer-local-lab.mjs
```

真实接入脚本会使用已保留的 `.local/local-lab/product-state.json` 复用 ID/幂等键，通过产品执行连接和同步；它不是纯只读命令，不删除已有资源。Observer 脚本会停止并在 finally 中恢复本项目 VM A，期间不得同时依赖 A 做其他验收。集成测试在独立 PostgreSQL schema 和临时凭证中运行。

本地引导拥有明确的 sudo 管理权限；导入的 cluster-admin 凭证按实际宽权限显示，不能称作最小权限。本次 SDK 探针另验证了实际受限 ServiceAccount 撤销与替换。常规管理身份的权限范围按目标显示，凭证到期、替换及 CA 变化均有明确路径；不静默修改已有集群的加密设置或 RBAC。

## 剩余关口与后续

- S2 本地产品路径已收口，现有三套集群用于继续实现 S3；新 Linux 生产镜像仍需单独构建与启动验证。
- 云端关口仍需在真实 VPS 完成 Ubuntu/CPU 架构、SSH 权限、入站防火墙/API SAN、固定版本初始化与持续观察；Oracle 控制面独立验证部署和容量，amd64 不能由 ARM64 本地测试推断。
- S3 将实现 Service/Deployment、OCI 公私镜像、实际资源应用、健康等待、重启/停止/恢复/删除、Pod 日志/指标及恢复对账。当前集群工作负载预览不等于服务管理或镜像发布。
- 公网应用入口、可信 HTTPS、持久卷/数据库、GitHub 构建及其余完整个人版能力仍按原开发计划验收；本记录不缩小完整项目目标。
