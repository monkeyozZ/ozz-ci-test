## 1. 项目优先的入口与上下文

主路径是：**登录 → 项目列表 → 创建项目时先选择承载服务器/集群 → 项目工作区 → 环境 → 服务 → 配置、部署和排障**。

- 登录后的工作起点是项目。服务器/集群属于基础设施入口，帮助选择项目承载位置，不取代项目工作区。
- 选择单台服务器时，实际选择其关联的单节点 Cluster；已有集群可能没有已登记的 Server。尚未关联 Cluster 的 Server 先进入接入流程，同一多节点 Cluster 不因多个 Server 入口而重复成为目标，也不把项目固定到某个 Node。
- 创建项目时先确定承载目标，再填写名称等项目信息。每个项目固定绑定一个 Cluster，普通编辑不能更换；所有 Environment、Service 和卷继承项目目标，创建/编辑环境或服务不再提供独立集群选择。项目工作区持续显示目标集群与环境。
- 没有可选目标时，提供“添加服务器 / 接入已有集群”路径，接入后返回项目创建流程；保存地址、通过预检和集群 Ready 是不同状态。
- 已登记但未验证的 Cluster 可在 S1 被选择并保存项目元数据；项目创建不要求真实接入已经完成。目标尚未验证时明确显示限制，发布前按真实连接、权限和能力检查并解释阻塞原因。
- 项目内管理服务、域名、卷、数据库和发布；平台级资源列表保留项目/环境归属，并可返回原工作区。
- 切换项目/环境、浏览器返回、从任务或告警跳转到服务，都必须保留准确上下文。迟到请求不得显示成新项目的数据。

同一项目的 production/staging 共用一个 Cluster；需要独立集群时创建不同项目。P1 配置复制可创建绑定另一目标的新项目，P2 数据迁移另有流程；Stitch 不增加直接切换已有项目承载位置或跨集群拖拽服务的动作。

## 4. 共用状态与交互变体

每个家族均继承下列适用变体。不能只完成正常数据页面；也不要求把所有组合机械乘成重复页面。

| 状态组 | 必须提供的表现与路径 |
| --- | --- |
| 全局壳层 | 桌面项目导航、环境/承载上下文、任务入口、当前管理员、主题、Cmd/Ctrl+K；命令面板只导航或打开正常表单，不绕过业务校验 |
| 初始与后台加载 | 初始内容骨架；后台刷新保留现有内容/滚动/焦点，标记刷新情况；不能每次轮询整页闪白 |
| 空、过滤空与缺失 | 从未创建资源、筛选无结果、资源已删除/404 分别设计；给出对应创建、清除筛选或返回项目路径 |
| 无权限与会话问题 | 401 回登录，403 解释受限范围；重新登录不自动重放危险写操作 |
| 断联与数据过期 | 显示最后成功观察时间；保留最后数据并标记陈旧，不填零、不换成 stopped；仅重试相关请求 |
| 表单与冲突 | 字段/行错误、重复名称、无效引用、revision 冲突、未保存离开；中文 IME 的 Enter/Esc 不误触提交/关闭 |
| 任务接收与执行 | 202 是已接收；queued、执行阶段、失败与终态有独立来源；排队原因和任务入口持久可见 |
| 取消与不确定结果 | 取消请求中不是 cancelled；网络中断后显示结果待确认，通过任务 ID 查询，不产生重复副作用 |
| 配置与实际状态 | 草稿、完整已发布快照、最近成功记录、实际运行分开；部分应用/漂移有解释，不能把旧成功记录当当前版本 |
| 敏感信息 | 密码、密钥、连接串秘密部分、Token 默认脱敏；复制按钮的范围清楚；秘密草稿不持久化，错误也不回显秘密 |
| 删除与数据保留 | 显示具体资源、所有权、依赖与保留策略；用户确认的是目标资源；后台实际清理状态可查，不能仅删除行后提示成功 |
| 平台恢复模式 | 全局持续显示只读/恢复锁，明确未恢复的写入能力；未知受管资源和更高 revision 不被静默覆盖 |
| 明暗主题 | Light、Dark、System；首屏不闪错主题，弹层/日志/图表/终端的主题继承和对比度一致 |
| 窄屏与缩放 | 1440、1024、390 CSS px 与 200% 缩放；导航收起，主上下文不丢失，宽表格/日志独立滚动，主要操作可触达 |
| 键盘与读屏 | Tab 顺序、焦点可见、弹层焦点恢复、图标名称、状态文本；异步更新不抢焦点或持续轰炸读屏播报 |
| 动效与性能 | 常规反馈遵守 PRD UX08，减少动效偏好有效；长任务不制造虚假进度，日志缓冲/DOM 有界，前端与 API 指标分别验收 |

## 5. 必须串联的任务闭环

以下路径应在 Stitch 设计稿/原型中能顺着状态走完，并在真实实现时分别验证。原型链接不构成真实 API 执行证据。

| 路径 | 页面串联 | 结束判据与异常分支 |
| --- | --- | --- |
| FLOW01 首次进入到项目 | UI01 → UI02 选择承载目标 → 必要时 UI08 登记/接入并返回 → UI02 确认 → UI03 | 项目与 production 已创建并固定绑定一个 Cluster；登记未验证仍可保存元数据；无目标、预检/接入失败和中途取消都能返回，不虚构 Ready |
| FLOW02 镜像到 HTTPS | UI03 → UI04 镜像 → UI05 配置 → UI06 发布 → UI07 实例/日志 → UI09 域名 | 目标版本真实健康，DNS/路由/证书分别就绪，外部访问成功；拉取、架构、探针和 DNS 失败有排查入口 |
| FLOW03 Git 自动发布 | UI12 Git/Registry/Builder → UI04 Git → UI06 推送/构建/发布 → UI07 日志 | commit、digest 与运行版本可追溯；伪造/重复、构建失败、无权限、产物缺失保留可定位结果 |
| FLOW04 停止、推送、恢复 | UI06 停止 → 收到 Git 提交 → 查看待发布版本 → 恢复旧已发布快照或明确部署并启动 | 恢复不包含草稿/新 commit；失联显示待执行，取消请求不冒充已取消 |
| FLOW05 数据持久化 | UI04 数据库模板 → UI10 卷/数据库 → UI05 应用连接注入 → UI06 发布 → UI07/UI10 验证 | PG/Redis 重建后数据保留；密码与主版本不能普通修改；保留卷有可见管理入口 |
| FLOW06 备份与恢复 | P0 UI10 指引/记录；P1 UI12 存储 → UI10 计划/手动备份 → 目标项目/环境下新服务/卷恢复与验证 | 集群从目标项目继承；数据正确性与恢复时间点明确；备份失败、过期、容量不足、校验失败和未切换状态都可见 |

## 8. Stitch 批次与完成标准

以家族为生成和审阅批次，先确定项目工作区与上下文，再复用全局组件；不能把全部需求压缩成五张概览图。

1. 每个场景记录：UI 编号、P0/P1/P2、F 编号、入口、项目/环境/承载目标、初始状态、主要动作、预期下一状态、异常返回路径。
2. 每个家族交付：主要页面、创建/编辑流程、适用的空/错误/执行/受限状态；对应深色/窄屏/键盘说明。共用弹层与控件可以复用，但业务语义不能省略。
3. 先串联 FLOW01–FLOW04 的项目、服务、发布闭环，再完成数据/网络/观测/维护与自动化家族；P1 仍需全部覆盖，不能以“后续”替代设计清单。
4. 页面使用一致的设计样例身份：项目、环境、承载集群、服务、部署和日志相互对应；域名/IP/凭证使用安全占位。Stitch 产物说明注明设计示例，不能宣称已连接真实资源。
5. 全局主题、焦点、IME、列表刷新、日志滚动、任务状态机和危险动作确认有明确交互说明。可点击连线不足以验证真实请求、取消、幂等或键盘行为，这些在实现阶段另行验收。
6. 完成记录分为“待设计、已有设计待核对、已审阅设计、已串联原型、已映射实现、已真实验收”。已有探索页必须按本清单补齐状态与关系，不能自动算作整个家族完成。
7. 收口时逐项检查 F01–F42 均有主要落点、必要异常状态和闭环；F43–F50 独立标注为未来概念。所有未知、未测试或未实现事项如实保留，不以成功文案掩盖。
