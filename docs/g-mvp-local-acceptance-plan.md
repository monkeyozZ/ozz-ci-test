### L06 复现要求与当前证据边界

以下保留恢复演练的要求，不作为重复执行整套演练的待办。原六次保留失败及两份备份的实际范围见[旧恢复记录](acceptance/g-mvp-recovery-local-lab.md)；恢复后 HTTPS、14.537213 秒独立元数据样本与 [21.559829042 秒联合样本](acceptance/g-mvp-recovery-joint-timing.md)分别留证。后者已包含 Builder/K3s 对账，以同一父时钟记录全部阶段；精确物理快照时间仍未知，故障时快照年龄的父调用界限为 2.674592458–5.409750375 秒。旧样本均无未完成 Task、未闭合本地 BuildRun 或 waiting WebhookTarget，不能据此声称实测了旧任务终态化。

1. 固定恢复专属资源和进程窗口，保存基准 target/Pod/PVC/资源 UID/revision、应用响应及独立 Builder 部署清单；使用当前公开恢复工具生成匹配数据库/密钥备份。
2. 通过正常产品动作产生一份备份后的完整新 publication，并创建一项备份未包含的受管资源。可结合已有 S6 运行记录形成远端清单比备份更晚的事实，不伪造 DB/run。
3. 只在 root 指定窗口关闭本控制面的 API/Worker/Redis，继续从运行面采集应用可用性/数据。记录停止、请求失败/成功与重新可用的实际时间；不要同时停止 K3s/应用来混淆故障来源。
4. 旧备份恢复到新空库和新密钥路径，原库/原密钥保留。旧会话失效、写入拒绝、Worker paused、旧 Outbox 不投递；对照运行面只读清单证明新 revision/未知资源未被删除或降级。
5. 按[恢复手册](control-plane-recovery.md)验证数据库外的 Builder 部署清单。CLI 只能枚举备份保留的 Builder 登记，备份遗漏的额外实例必须通过独立清单发现；失联、缺页、未知/未结束 run 或错误签名均保持锁，不能等一段时间便假定结束。
6. 未解决的 K3s/Builder 差异保留锁并如实记录。另以已核对一致的恢复样本验证受保护的显式解锁、新 generation 的新诊断能执行、旧任务不能重放。不得把无法安全解锁的旧样本改写成成功，或用更新归档覆盖失败证据。

RPO 分别报告控制面最后一致备份时间与数据备份的实际恢复点；RTO 分开报告恢复导入、只读可用、完成对账并恢复写入的时间。控制面停机时某段窗口内应用未中断，只说明该观测窗口，不承诺 HA/SLA 或零故障。
