# Console v3 交互调整

本轮根据用户“直接按 Zeabur 的交互来，不要遗漏功能点”的要求，完善[完整原型](../designs/console-v3/index.html)并调整真实 Console。保留 Ozz 的紫色、明暗主题、已有 API 与资源归属。Chrome 实际观察范围见[参考记录](../designs/console-v3/reference-notes.md)，没有提交 Zeabur 创建或部署；研究标签和临时控件读取状态已恢复。

## 操作入口

| 日常任务         | 当前入口与行为                                                                                 |
| ---------------- | ---------------------------------------------------------------------------------------------- |
| 全局导航         | 项目、服务器、设置；顶栏活动与快速打开继续可用                                                 |
| 打开项目         | 项目卡片优先进入所属服务；服务总览、项目设置、整合和服务列表在项目内可达                       |
| 创建项目         | 先选唯一 Cluster；名称可选，标识自动生成，更多设置保留标识与描述；完成后进入首服务弹窗         |
| 添加服务         | 原项目/服务页保持为背景；GitHub、Docker、应用模板、数据库四入口；逐步返回与来源草稿保留        |
| 配置与部署       | 常用字段优先、附加配置展开；先保存服务草稿，再原地核对并确认部署；修改和响应丢失重试复用原身份 |
| 服务详情         | 服务状态、环境变量、用量、网络、数据与存储、设置六页签；变量和运行配置共用草稿                 |
| 发布、日志、历史 | 服务内面板，返回时保留页签与编辑；实际任务仍可独立打开、刷新与追踪                             |
| 运行操作与删除   | 重启、停止、恢复放在更多操作；删除继续审查依赖与保留卷，不等于销毁数据                         |
| 所有资源         | 设置的“资源与任务”和项目列表快捷入口；服务、模板、数据库、卷、域名、部署、操作任务均可达       |
| 项目环境         | 环境管理移至项目设置；完整确认单环境后隐藏选择，多环境与未完成分页继续显示                     |
| 管理与数据维护   | 服务器/集群、凭证、GitHub、Builder、Registry、网络与卷维护保留现有完整页面和审查               |

Environment 组织同一项目中的服务、配置、网络和数据，并非区分数据库类型。它与项目目标的后端模型没有删除；切环境不会移动服务或复制数据。保留数据不能依赖已删除的源服务才能访问。

## 连续流程与保护

- 添加服务使用查询参数保持真实背景页面；旧 `/projects/:id/services/new` 链接兼容重定向。关闭创建只检查该弹窗的草稿，不清除背景编辑。
- 编辑区域初次访问后保活；变量、`.env` 原文、Git、网络、挂载和数据库连接在切页签后保留。隐藏字段的校验先打开正确分组再定位。
- 保存服务后先固定服务 ID，再执行查询刷新或部署核对。`createdService` 链接恢复时核实项目、环境、目标和来源；未知结果禁止换来源，重试复用原请求与幂等键。
- 项目、镜像和 Git 创建的可选幂等键兼容旧调用；同请求返回原结果，改变请求返回冲突。秘密配置指纹使用用途隔离的 HMAC，保留密钥支持轮换后的重放。已有模板回执保持兼容。
- 旧 `source/configuration/review/logs/deployments` 页签链接定位到来源/运行配置/相应面板。日志的实例、容器与待发布 Git 目标保持原身份。
- 草稿、发布快照、运行观察、历史任务分别呈现。数据库初始化保护、完整存储引用、版本冲突、预览过期、恢复只读和维护锁继续生效。

## 原型与实际能力

原型包含服务与完整管理流程，覆盖规划映射到原 28 个页面、78 个场景、12 条连续流程和 F01–F50。规划映射不是所有场景已验收的证明，实际浏览器检查范围以原型 README 和结果文件为准。

内置模板为 Docker、Node.js 示例、静态站点示例、PostgreSQL、Redis。Node/静态模板使用既有镜像与示例；Git 仍需要 Dockerfile。手工备份/恢复记录登记操作者证据，不执行自动导出或数据恢复。终端、自动备份、历史 digest 回滚及其他未接入 API 的能力仅在原型中明确标为规划演示。
